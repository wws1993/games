# 乐斗三消-原型开发路线

## 1. 文档目标

本路线用于把“乐斗式回合战斗 + 共用棋盘三消”从概念快速推进到可试玩原型，优先验证玩法是否成立，而不是一开始追求完整内容量。

## 2. 原型开发原则

1. 优先验证核心博弈，不优先堆内容。
2. 优先让回合、消除、技能、演出串起来。
3. 优先做可调参结构，方便快速试错。
4. 优先建立最小 AI，而不是复杂智能。

## 3. 里程碑拆分

建议拆成五个阶段。

## 4. 阶段一：战斗骨架

### 4.1 目标

先跑通“进入一场战斗并轮流行动”的最小闭环。

### 4.2 交付内容

1. 战斗场景基础布局
2. 玩家与敌人的站位占位图
3. 生命条与回合提示
4. 基础战斗状态机
5. 回合切换流程

### 4.3 状态机建议

建议拆为以下状态：

1. `battleStart`
2. `turnStart`
3. `boardInput`
4. `boardResolve`
5. `skillCastWindow`
6. `turnEnd`
7. `battleEnd`

### 4.4 验收标准

1. 能进入一场战斗。
2. 能显示当前是谁的回合。
3. 能在不接入完整三消前，用假按钮推进回合。
4. 一方生命归零时可正常结束。

## 5. 阶段二：三消核心

### 5.1 目标

把棋盘变成真正可操作、可消除、可连锁的共用系统。

### 5.2 交付内容

1. `7 x 7` 棋盘生成
2. 邻格交换
3. 非法交换回弹
4. 三消检测
5. 下落补棋
6. 连锁结算
7. 特殊棋子的第一版支持

### 5.3 数据结构建议

建议提前抽象：

- `BoardCell`
- `GemColor`
- `SpecialGemType`
- `BoardActionResult`
- `CascadeResult`

### 5.4 关键验证

1. 共用棋盘逻辑是否清晰。
2. 回合内只允许一次有效交换是否足够顺手。
3. 连锁频率是否合理，是否会拖慢节奏。

## 6. 阶段三：资源与技能

### 6.1 目标

将消除收益映射为技能进度，并引入“手动释放”的选择。

### 6.2 交付内容

1. 五色进度条
2. 技能充能规则
3. 玩家技能按钮
4. 技能满足高亮
5. 技能释放窗口
6. 技能目标与结算

### 6.3 第一版技能配置建议

玩家：

1. 红色单体伤害
2. 蓝色眩晕
3. 绿色护盾
4. 黄色改色

敌人：

1. 红色重击
2. 蓝色打断
3. 紫色易伤

### 6.4 验收标准

1. 消除后能稳定获得对应进度。
2. 技能满足后不会自动释放。
3. 玩家可以选择释放或保留。
4. 技能释放能改变战斗节奏或棋盘局面。

## 7. 阶段四：敌方 AI

### 7.1 目标

让敌人具备最基本的“抢色、拆局、放技能”意识。

### 7.2 交付内容

1. 合法交换搜索
2. 基于权重的走法评分
3. 技能释放优先级判断
4. 不同敌人配置不同权重模板

### 7.3 AI 简化公式建议

每个候选行动可按以下维度评分：

- 消除数量收益
- 目标颜色收益
- 是否生成特殊棋
- 是否破坏玩家明显高收益入口
- 是否满足本回合可放技能
- 是否避免给玩家留下更大收益

### 7.4 验收标准

1. 敌人不会随机乱换。
2. 敌人能偏向自己擅长的颜色。
3. 敌人偶尔会主动破坏玩家好局。
4. 敌人会在合理时机释放技能。

## 8. 阶段五：演出与打磨

### 8.1 目标

把玩法反馈从“能玩”提升到“像乐斗”。

### 8.2 交付内容

1. 消除特效
2. 角色出招动画
3. 受击与击退反馈
4. 状态图标表现
5. 回合切换提示
6. 胜负结算界面

### 8.3 演出优先级

优先做：

1. 技能释放瞬间
2. 受击反馈
3. 连锁成功反馈

后做：

1. 待机动画细节
2. 背景氛围细节
3. 复杂镜头运动

## 10. 推荐开发顺序

建议不要一开始重做全部现有结构，而是并行保留原型代码，再逐步切到新玩法。

推荐顺序：

1. 新建独立的 `battle` 与 `board` 模块
2. 新建一个新的 `BattleScreen`
3. 先用占位图完成回合与棋盘交互
4. 再逐步接入技能、AI、演出
5. 最后再清理旧原型与无关逻辑

## 11. 第一版可试玩范围

若只做一个能验证乐趣的试玩版本，建议控制在以下范围：

1. 1 个玩家角色
2. 3 个敌人模板
3. 1 张战斗场景
4. 5 种颜色
5. 4 个玩家技能
6. 3 个敌人技能
7. 5 个基础状态/棋盘效果以内

这样能保证测试时，玩家已经能体验到：

1. 颜色争夺
2. 回合压制
3. 憋技能反打
4. 棋盘干扰

## 12. 风险点与规避方案

### 12.1 风险一：输出技能压倒一切

表现：

玩家永远只追红色，不关心棋盘控制。

规避：

1. 提高控制和操盘技能的节奏收益。
2. 让敌方爆发前摇明显，迫使玩家做干扰。
3. 让部分高伤技能依赖铺垫状态，而不是单独强。

### 12.2 风险二：共用棋盘带来的挫败感过高

表现：

玩家感觉自己每次铺局都在帮敌人，不知道怎么应对。

规避：

1. 第一版敌方 AI 不要太强。
2. 给玩家更多棋盘技能来主动拆局。
3. 教学中明确提示“不要只看自己这一步，也要看敌人下一步”。

### 12.3 风险三：节奏过慢

表现：

单回合等待时间长，动画拖沓。

规避：

1. 限制每回合只进行一次有效交换。
2. 压缩自动连锁播放时长。
3. 技能动画默认短促，长动画只留给大招。

### 12.4 风险四：AI 过弱或过蠢

表现：

敌人不会拆局，体验像打木桩。

规避：

1. 至少实现“目标颜色偏好”。
2. 至少实现“破坏玩家明显高收益入口”。
3. 给不同敌人准备不同评分权重表。

## 13. 测试指标建议

在内部试玩时，建议记录以下指标：

1. 单局平均时长
2. 平均每局技能释放次数
3. 棋盘技能使用占比
4. 玩家失败原因分布
5. 玩家是否能主动保留技能等待时机
6. 玩家是否能理解敌我共用棋盘的博弈点

## 14. 下一步细化建议

当第一版原型跑通后，优先继续细化以下文档：

1. 角色与技能清单
2. 棋盘特殊棋规则
3. AI 权重表
4. 新手教学流程
5. 关卡与敌人曲线
